问题

一天的工作散落在十几个会话里，还有一部分不在任何会话里。

改了什么、为什么改、在哪里卡住，这些都在对话里，提交记录里几乎没有。到了周五就全忘了。

而和同事的一次讨论、在真机上的一次测试、事情最后成没成，没有哪个会话看得见。Agent 能替我们做出很好的结果，却没法替我们度过这一天。

两种笔迹，一份日志

Agent 起草，你落笔。

两种笔迹在同一页上，每个项目一份大纲，彼此分得清。紫色是你写的，重新生成报告也不会碰它。

Agent 写

  • 会话里发生了什么：做了什么、改了哪里、在哪里卡住
  • 每条结论都锚定到原始轮次，由程序校验
  • 每次重新生成或更新，都是一份新的草稿

你写

  • 会话之外发生了什么，事情成没成
  • 当天与项目的笔记，以及对 Agent 要点的批注
  • 项目页上的背景与计划
工作方式

收拢、起草、落笔。

整理日志应该是每晚几分钟的小仪式，而不是一键生成的黑箱。

1

收拢

兰台增量读取各个 Agent 的会话文件，按天切分长会话。你把它们放进自己建好的项目，忽略无关的；规则和模型给出建议，由你确认。

2

起草

每个会话先压缩成带缓存的摘要，模型再按项目起草报告：核心结论在前，细节与锚点在后。周报和月报在日报的基础上汇总。

3

落笔

在草稿旁边写下只有你知道的事：当天与项目的笔记、对 Agent 要点的批注。还没生成报告时，也可以先写。

功能

不只追求快，更要经得起核对。

报告只有能核对才有用。兰台让每一句话都能找到背后的那段工作。

两种笔迹，一份日志

Agent 的草稿和你的笔记在同一页上。紫色是你写的；可以切换为两者并排、只看 Agent 或只看你写的。

你来归类，模型起草

项目由你定义。目录、远程仓库规则或模型给出建议，你接受后才归入。可以框选多个会话，一次移动或忽略。

每条结论可追溯

结论带有 [#S12.T5] 这样的锚点，点开就是它出自的那一轮对话。锚点由程序校验，模型编造的会被剔除。

你写的字经得起重写

点 Update 只重写有变化的项目。你的笔记永远不会被改动，你改过的 Agent 原文也原样保留，并带有修订标记。

日报、周报、月报

周报按项目把一周的工作聚类成事项，月报在周报之上汇总。项目视图可以按天、周或月回顾任意项目，笔记也在其中。

工作统计看板

活跃时长（并行会话只算一次）、连续活跃天数、常用工具、每天的工作节律，以及各模型的 Token 用量与缓存命中率。

隐私

你的会话只留在你的电脑上。

Agent 日志里有私有代码、文件路径，有时还有密钥。兰台按这个标准对待它们。

始终只读

兰台从不写入、移动或删除 Agent 数据目录里的任何文件。这些目录里如果还有凭据，它只读会话部分。

两次脱敏

密钥、令牌、私钥块和 .env 一类的值，在写入本地数据库前清除一次，发给模型前再清除一次。

密钥存在钥匙串

API 密钥存在 macOS 钥匙串里，不进配置文件、数据库或日志。Git 远程地址只记 host/owner/repo，内嵌的令牌不保留。

封闭生成

模型写报告时禁用所有工具，也不落盘。会话里夹带的指令只被当作文字，不会被执行。

模型由你选

可用任何 OpenAI 兼容接口，包括 Ollama 或 LM Studio 运行的本地模型，数据不出电脑；也可以沿用已登录的 Claude Code。

无账号，无遥测

不用注册，没有云同步，也不做统计上报。所有内容都在本地 SQLite 数据库里，其中的会话数据随时可以从 Agent 日志重建。

开始使用

下载，扫描，落笔。

免费的 macOS 应用，支持 Apple 芯片与 Intel，内置命令行工具。兰台还在 beta 阶段：1.0 之前，更新可能改变数据格式，更新日志会写明该怎么做。

下载 macOS 版

桌面应用

打开 .dmg，把兰台拖进「应用程序」。它还没有苹果开发者签名，第一次打开时，在「系统设置 → 隐私与安全性」里点仍要打开，或者在终端执行：

xattr -dr com.apple.quarantine \ /Applications/Lantai.app

然后在设置 → 模型里选好模型（查找本机工具可以添加已登录的 Claude Code），点扫描，把当天的会话归到项目里，再点生成。

命令行

同一套引擎的命令行版本 aj，在「设置 → 系统 → 命令行工具」里安装。它会链接到 ~/.local/bin/aj，所以这个文件夹要在 PATH 里：

export PATH="$HOME/.local/bin:$PATH" aj scan aj report daily # 把第一行加进 ~/.zshrc 即可长期生效

首次扫描读取最近 90 天的会话。执行 aj --help 查看全部命令。

平台macOS 11 或更高版本，Apple 芯片或 Intel。
模型OpenAI 兼容接口、本地模型，或已登录的 Claude Code。
从源码构建需要 Rust（stable）与 Node.js，在 app/ 里执行 npm run build:app。详见 README。
初衷

Agent 没法替我们度过这一天

如今，许多工作都交给了 Agent：开发产品、排查问题、起草邮件、做实验、写文档。人把问题说清楚，Agent 很快就把事情做完。会话之外做了什么，事情最后成没成，自己怎么看这件事，这些只有人自己知道。

这份记录对 Agent 也许没什么用，对项目的完成也许也没什么用，但对人有用。

翻开日报、周报、月报，能看到自己和 Agent 一起做成了许多事，有些是以前没想过能做到的。这份意义属于自己。

兰台也是一次尝试：人和 Agent 怎样一起工作，又怎样一起留下记录。如果你对其中的分寸有想法，欢迎提 Issue。

名字

为什么叫「兰台」？

兰台是汉代宫廷收藏典籍图书的地方。在这里任职的官员负责校勘典籍、起草文书，班固就曾在兰台修撰史书。后来，「兰台」也成了史官的代称。

兰是兰花，在中国文化里象征安静、内敛的品格：不张扬，却自有芬芳。

把每天零散的工作收拢起来、整理有序、存档备查，正是这个应用想做的事。
